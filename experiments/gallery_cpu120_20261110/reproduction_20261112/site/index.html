Scope matters. The historical screen used adapted, approximately 350,000-parameter byte-level models for 120 CPU-seconds. It does not establish the best full-scale architecture. This update adds reproduction repairs and verification, not new training runs.

103 or 105?

The pinned export contains 105 unique indices, names and exact program hashes. No canonical subset resolving the historical “103 architectures” count has been established. Different source files do not necessarily mean distinct architectural ideas.

What the independent check found

  • All five downloaded public inputs match their pinned hashes. The training data, all held-out windows and both evaluation arrays match the published ledger.
  • All six checkpoints load and match the recorded state hashes, parameter counts and keys.
  • 0 of 6 meet the original strict numerical tolerance on the different CPU and PyTorch version. Largest aggregate loss shift: 0.000136117226 nats per byte. Largest window shift: 0.003269 nats. Original tolerances: 1e-6 aggregate, 2e-6 per window.
  • The check used Xeon Skylake and PyTorch 2.10 CPU execution; original training used an AMX-capable CPU and PyTorch 2.6. Different arithmetic is a plausible cause, not an isolated causal explanation.

The original within-machine results remain intact. This is a portability finding, not a new quality winner.
