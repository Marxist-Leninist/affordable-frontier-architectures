# ASI-Arch #458 versus AGILLM: completed comparison

## Two different questions, two different answers

1. Under the same reduced training CPU budget, the model using the original #458 mixer learned next-byte prediction better than the tested current and historical AGILLM source adaptations.
2. On an identical-byte checkpoint diagnostic, the existing full native600B-class checkpoint receipt scored better than our tiny349,944-parameter DLGM checkpoint. The reduced experiment does not show DLGM beating the actual600B model.

## Controlled reduced training study

All18 jobs completed: six configurations, three seeds each,1,200 trainingCPU seconds per job. L8/d128, context256, batch2, byte vocabulary257. Fixed public WikiText split/revision, common per-seed data stream, fixed holdouts. The main comparison has about3.079M scalar coefficients per model. DLGM uses FP32/AdamW; native uses binary latents and its backward-time updater, plus AdamW for floating parameters. Equal coefficients are not equal memory or active compute. Historical source heads use the common AR-only recipe, not their original multimode recipes.

## Serving, memory and convergence

Full-prefix CPU recomputation for eight generated bytes, two warmups and seven measured rounds per seed. No cache for either model; #458 recurrent cache was not supported. At512-byte prefix, DLGMtotal seed medians were0.743–0.810seconds versus nativeMoE0.598–0.663seconds; at1024,1.324–1.410 versus1.162–1.235seconds. At128, DLGM per-seed medians were slightly lower (0.28256–0.29045seconds versus0.29120–0.30295seconds); individual timing rounds overlap. DLGM process peak RSS746–756MiB versus nativeMoE575–576MiB; this is whole-process training/evaluation memory, not serving-only storage. No GPU or energy measurement occurred.

Both main models were still learning at the20minute limit. Native validation NLL600→1200seconds improved2.13855→1.91722; DLGM1.62057→1.51708. Results at larger budgets remain untested. DLGM saw fewer training targets, roughly1.494M versus nativeMoE2.444M per seed.

## Existing-checkpoint identical-byte diagnostic

This separate observational test used83,253 target bytes from eight length-selected English FineWeb-Edu documents. Native saved evaluation receipts and the tiny DLGM checkpoint score exactly the same decoded byte spans. Native numbers are canonical o200k token-path NLL divided by decoded bytes, not marginalized probability over all tokenizations. These are different model sizes, tokenizers, data histories and compute budgets, not an architecture-controlled comparison.

| Recorded checkpoint | Bits per target byte, lower better |

| Native step5053 (512B-class/L320) | 1.847880 |
| Native step5750 (512B-class/L320) | 1.882864 |
| Native step6001 (600B-class/L380) | 1.881559 |
| Native step6250 (600B-class/L380) | 1.860470 |
| DLGM v54 seed1,349,944 parameters | 2.816439 |

All eight DLGM repeated outputs were exact; future-token perturbation changed earlier logits by0. Finite checks and unchanged weights passed. Native6250 was the latest available verified evaluation receipt when added before DLGM scoring; it does not certify current live weights. The native checkpoint scores better on this pilot. Neither outcome proves general intelligence, architecture superiority, causal repair, production serving economics or a600B training recommendation. Historical contamination is unknown.
